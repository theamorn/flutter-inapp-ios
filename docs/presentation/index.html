Ten years of all-or-nothing.

"Team Native" vs "Team Cross-Platform"

⚔️
Image Placeholder

Tug-of-war graphic: "100% Swift/Kotlin" vs "Rewrite Everything".

Foundation • Act 3

Three ways a mobile screen draws.

Widgets. Web. Owned canvas. Flutter Add-to-App is the third.

1. Platform widgets

UIKit / Compose. The OS owns layout, accessibility, and look. Login, Home, forms stay here.

2. Web document

DOM + compositor. Great for copy that changes weekly. Weak at deterministic 120 fps physics.

3. Owned canvas

OS gives a UIView or Surface. You paint every pixel. Unity, custom Metal, Flutter Add-to-App.

  • This is a board, not a code tour.
  • Flutter inside a native app is column 3: give me a canvas.
  • Do not rewrite forms onto a canvas. You will lose VoiceOver.
Foundation • 120 Hz

8.3 milliseconds.

That is the entire ProMotion budget. UI isolate + Raster both have to fit.

60 Hz → 16.6 ms 120 Hz → 8.3 ms ← ProMotion UI isolate layout, widgets, game tick Raster Impeller → Metal / Vulkan HUD is native-owned CADisplayLink / Choreographer task_info / Debug.getPss Flutter reports UI + raster batches only
  • If Flutter graded itself, you would be right to call the meter rigged.
  • Jank is two diseases: fat UI time vs fat raster time. Read both clocks.
  • Users feel the worst frame, not the average. Say "average" when you quote the HUD.
Foundation • Architecture

Identical pixels is a choice.

Two teams, two shaders, two “looks close enough.” One canvas, one picture.

Two implementations iOS Metal Android AGSL / RenderNode ↓ two bugs + beige parity One owned canvas ↓ one picture (how games already work)
  • Stop here. Do not explain Impeller internals yet.
  • We already accepted a runtime tax for games. A promo screen is the same problem.
The Solution

Enter the Middle Ground.

Introducing Flutter for offloading complex UI.

🚀
Image Placeholder

Flutter as an embedded graphics card slotted inside a native smartphone.

  • I want to introduce the pragmatic middle ground: Flutter.
  • Don't think of Flutter as an app replacement.
  • Think of it as a specialized, high-performance rendering engine embedded inside your native app.
Under The Hood

Flutter owns the canvas.

Direct to Metal and Vulkan at C++ machine level.

⚙️
Image Placeholder

Impeller engine compiling AOT command buffers straight to Metal and Vulkan.

  • Why Flutter? Because like Unity, Flutter does NOT map to OEM native buttons or DOM elements.
  • It asks for a surface and paints every pixel itself.
  • With Impeller, it compiles AOT to native machine code with zero runtime shader compilation jank.
Myth Buster

You don't rewrite your app.

Flutter is just a view asking for a canvas.

🖼️
Image Placeholder

Native UIViewController handing an empty canvas frame to Flutter.

  • "Wait, doesn't Flutter mean throwing away our Swift/Kotlin app?"
  • Absolutely NOT.
  • Under the hood, Flutter is just a view controller.
  • It asks iOS: "Give me a UIViewController." It asks Android: "Give me a FragmentActivity."
Architecture

Add-to-App.

Native owns the app; Flutter paints the screen.

🧩
Image Placeholder

Native iOS tab bar with Tab 3 glowing as an embedded Flutter canvas.

  • This pattern is called Add-to-App.
  • Keep your native navigation, push notifications, Bluetooth, and standard forms.
  • When you reach that one screen with impossible animation requirements, hand the canvas to Flutter.
Architecture • Act 4

One group. Three lazy engines.

Hidden tabs pause. First visit is when the HUD shows the cost.

Native window + native HUD ├── Tab 1 UIKit / Compose Home ├── Tab 2 WKWebView settings └── FlutterEngineGroup("hybrid-demo") ├── /game first visit to tab 3 ├── /glass first visit to tab 4 └── /scene first visit to tab 5
  • Do not pre-warm at launch — it hides the incremental memory story.
  • Hidden tabs pause so Flappy Cat does not run behind Home.
  • Quote costs once: 4–6 MB bundle, ~13–19 MB first engine, ~180 KB / 1.4 MB extras.
Memory Benchmark
~180 KB
The memory cost of an extra Flutter engine on iOS.
Mechanism: FlutterEngineGroup
Shared: GPU Context • Isolate Group • Fonts
  • "Doesn't embedding Flutter eat 100MB of RAM?"
  • No. That's the old 2019 myth.
  • With FlutterEngineGroup, engines share the GPU context and isolate snapshots.
  • An additional engine costs ~180 KB on iOS and ~1.4 MB on Android. That's less than loading a single high-res image!
The Comparison

Like Unity in an app.

Without the 100MB baggage.

⚖️
Image Placeholder

Heavy Unity crate (3–6s boot / 100MB) vs feather-light Flutter badge (150ms / 4MB).

  • "So it's basically like putting Unity in your app?"
  • Conceptually, yes—you get a unified 2D/3D canvas.
  • But without the game engine tax: Unity takes 3 to 6 seconds to boot and adds 100MB.
  • Flutter launches in 150ms and spawns cached tabs in 10ms.

The Strategy

Choose tools like an architect.

Stop treating frameworks as religions.

🏛️
Decision Pyramid

3-tier pyramid: Native Core → Web Legal/FAQs → Flutter Add-to-App Canvas.

  • Don't let dogmatic purity dictate architecture.
  • If someone says rewrite your native navigation in Flutter, say no.
  • If someone says write custom Metal and Vulkan shaders twice, say no.
  • Be the pragmatic architect who picks the right tool for the job.

We solve problems with software.
