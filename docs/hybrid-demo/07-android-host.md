# 07 — Android host (minimal: tabs 1 + 3)

## Goal

A native Android app that proves the parity claim: the **same** Flutter module, hosted under **visibly Android** native chrome, reporting the **same** performance numbers. Two tabs only — native Home and the Flutter game.

## Prerequisites

- `02-ios-host.md` complete (Dart-side routing and telemetry exist).
- `04-flappy-cat.md` complete (there is a game to host).
- `03-native-web.md` complete (there is an iOS Home layout to mirror).
- Read `ARCHITECTURE.md` for engine topology, routes, and the telemetry contract.

## Repo facts you need

- **No Android host app exists in this repo.** `flutter_native/android/` is a different thing entirely — the Android shell of the standalone `flutter_native` Flutter app. Do not confuse the two, and do not build on top of it.
- `flutter_module/.android/` is generated by `flutter pub get`. It contains `include_flutter.groovy`, which is what a host Gradle project includes. It is gitignored; regenerate rather than commit.
- `flutter_module/pubspec.yaml` declares `module: androidPackage: com.example.flutter_module`.
- The iOS Home tab (`cool-ios/cool-ios/HomeViewController.swift`) is the layout to mirror.

## Scope discipline

**Two tabs. Not five.** The Android host exists to make one point — same Flutter, different native chrome, same numbers — and that point is fully made with tabs 1 and 3. Do not build the WebView, glass, or 3D tabs here unless the presenter explicitly asks. (Tab 4's Android parity is verified separately by running route `/glass` on the module standalone; see `05-liquid-glass.md`.)

## Implementation notes

Kotlin, Jetpack Compose, Material 3.

### Add-to-app wiring

In `settings.gradle.kts`:

```kotlin
val filePath = settingsDir.parentFile.toString() + "/flutter_module/.android/include_flutter.groovy"
apply(from = File(filePath))
```

In `app/build.gradle.kts`: `implementation(project(":flutter"))`.

Run `fvm flutter pub get` in `flutter_module` first, or `.android/` will not exist and the Gradle sync fails with a confusing path error.

### Engines

Mirror the iOS structure from `02-ios-host.md`:

```kotlin
val group = FlutterEngineGroup(context)          // io.flutter.embedding.engine.FlutterEngineGroup
val engine = group.createAndRunEngine(context, DartExecutor.DartEntrypoint.createDefault(), "/game")
FlutterEngineCache.getInstance().put("game", engine)
```

Host it with `FlutterFragment.withCachedEngine("game").build()` inside the tab's container, so the `NavigationBar` stays visible above it. Same rule as iOS: **the Flutter surface must not cover the native chrome.**

Spawn lazily on first tab selection, not at app start, and record the memory delta into the HUD — the same live cost readout as iOS.

### Home tab

Mirror the iOS Home **layout** — same sections, same information architecture — using Material components: `Switch`, `SegmentedButton`, `Card`, `ListItem`, `FilledButton`.

The point on stage is precise: *layout is the same, components are visibly different, and both are genuinely native to their platform.* That is the "native look and feel" argument, and it is the reason tab 1 is not built in Flutter.

### HUD

Same contract as iOS (`ARCHITECTURE.md`): `Choreographer.FrameCallback` for host cadence, `Debug.MemoryInfo` / `Debug.getPss()` for memory, and Flutter's own numbers over `com.theamorn.hybrid/telemetry`. Same visual design as the iOS HUD, so the two can be photographed side by side.

### Manifest

Include the Flutter GPU meta-data even though tab 5 is not built here — it costs nothing and keeps the hosts symmetric:

```xml
<meta-data android:name="EnableFlutterGPU" android:value="true" />
```

## Gotchas

- `flutter_module/.android/` is generated. If Gradle sync fails on a missing path, run `fvm flutter pub get` in `flutter_module` and re-sync.
- Match `compileSdk` / `minSdk` to what the Flutter module's generated Gradle expects, or the merge fails with version conflicts.
- Android high-refresh-rate behaviour is device-dependent and there is no single flag equivalent to iOS's `CADisableMinimumFrameDurationOnPhone`. Note on the HUD which device you are on and what its panel actually does, so the comparison with iOS is honest rather than confusing.
- Do not commit `.android/` or any generated Flutter Gradle output.

## Acceptance criteria

- [ ] `cool-android` builds and installs in release mode.
- [ ] Login → 2-tab `NavigationBar`.
- [ ] Home tab is native Compose, mirroring the iOS layout with Material components.
- [ ] Game tab runs the same Flutter game from the same `flutter_module`, under a still-visible `NavigationBar`.
- [ ] Engine spawns lazily on first tab selection; HUD shows the memory delta.
- [ ] HUD shows the same metrics as iOS, in the same visual design.
- [ ] Nothing in `flutter_module` was forked or special-cased for Android.

## How to verify

Physical Android device, release mode.

1. Log in, switch tabs, confirm the `NavigationBar` stays visible over the Flutter surface.
2. Play the game. Compare HUD numbers against the iOS device running the same tab.
3. Put both devices side by side on tab 1, then both on tab 3. Photograph both pairs — tab 1 should look clearly platform-native on each; tab 3 should look identical on both. **That pair of photos is the parity slide.**
4. Confirm `git status` shows no generated `.android/` output staged.
